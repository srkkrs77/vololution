# 📖 seoVolo — справочник по параметрам

**Для кого:** администратор сайта, редактор, любой, кто хочет понять что за что отвечает.  
**Не для кого:** программисты. Технический разбор кода — в других файлах.  
**Формат:** каждый параметр — что это, зачем, пример, кто использует.

---

## ЧАСТЬ 1. БАЗОВЫЕ ПОНЯТИЯ

Прежде чем разбирать TV и настройки — разберёмся, что это за технологии.

### 1.1. Title (`<title>`)

**Что это:** заголовок страницы.  
**Где видно:** синяя строка в результатах поиска Google и Яндекса. Также показывается во вкладке браузера.  
**Зачем нужно:** по нему пользователь решает — кликнуть или нет. Главный фактор CTR (кликабельности) в поиске.  
**Кто использует:** Google, Яндекс, Bing, все поисковики.  
**Пример:** «Услуги SEO в Москве — цены и кейсы | Studio X»  

### 1.2. Description (`<meta name="description">`)

**Что это:** краткое описание страницы.  
**Где видно:** серый текст под заголовком в результатах поиска.  
**Зачем нужно:** помогает пользователю понять, о чём страница. Влияет на кликабельность, но **не** на позицию в поиске.  
**Кто использует:** Google (иногда подменяет своим фрагментом), Яндекс, Bing.  
**Пример:** «Агентство стратегических коммуникаций. Позиционирование, Thought Leadership, PR для бизнеса. 10 лет на рынке.»  

### 1.3. Keywords (`<meta name="keywords">`)

**Что это:** список ключевых слов страницы.  
**Где видно:** нигде. Устаревший тег.  
**Зачем нужно:** ни для чего. Google игнорирует с 2009, Яндекс с 2022, Bing давно.  
**Кто использует:** никто.  
**Пример:** «seo, продвижение, москва, услуги»  

### 1.4. Canonical (`<link rel="canonical">`)

**Что это:** ссылка на «главную» версию страницы.  
**Зачем нужно:** если одна и та же страница доступна по нескольким URL — говорим поисковику: «главный вот этот, остальные — дубликаты». Без этого поисковик может сам выбрать не тот URL, и весь трафик уйдёт на него.  
**Кто использует:** Google, Яндекс, Bing.  
**Пример:** страница `site.ru/o-nas/?page=2` и `site.ru/o-nas/` — одинаковый контент. Canonical говорит: главный — `site.ru/o-nas/`.  

### 1.5. Robots meta (`<meta name="robots">`)

**Что это:** команда поисковикам — индексировать страницу или нет.  
**Зачем нужно:** управлять, что попадает в поиск, а что нет. Технические страницы, «спасибо за заказ», устаревшие акции — закрываем от индексации.  
**Кто использует:** Google, Яндекс, Bing.  
**Пример:** `<meta name="robots" content="noindex, nofollow">` — не индексировать, не обходить ссылки.  

### 1.6. Open Graph (OG)

**Что это:** набор тегов для красивого превью ссылки в соцсетях.  
**Зачем нужно:** когда ты делишься ссылкой в Telegram, VK, Facebook — показывается картинка, заголовок, описание. Без OG — покажется случайный кусок контента.  
**Кто использует:** Telegram, VK, Facebook, WhatsApp, LinkedIn, Slack.  
**Пример:** тег `og:image` = `https://site.ru/images/preview.jpg` → в Telegram покажется эта картинка.  

### 1.7. Twitter Cards

**Что это:** то же, что Open Graph, но для Twitter/X.  
**Зачем нужно:** красивое превью при шеринге в Twitter/X.  
**Кто использует:** Twitter/X.  
**Пример:** `twitter:card` = `summary_large_image` → большое превью с картинкой во всю ширину.  

### 1.8. Schema.org / JSON-LD

**Что это:** структурированные данные — машиночитаемое описание страницы.  
**Зачем нужно:** поисковик понимает, что на странице (статья, товар, услуга, FAQ) и показывает **расширенный сниппет**: рейтинг со звёздочками, дату, автора, цену, ответы на вопросы.  
**Кто использует:** Google, Яндекс, Bing.  
**Пример:** товар со Schema.org Product + отзывы → Google покажет ★★★★★ 4.5 в выдаче.  

### 1.9. Hreflang (`<link rel="alternate" hreflang="...">`)

**Что это:** указание языковых версий страницы.  
**Зачем нужно:** если сайт мультиязычный — говорим поисковику: «вот русская версия, вот английская, вот немецкая». Google покажет нужную версию пользователю по языку.  
**Кто использует:** Google, Яндекс (частично).  
**Пример:** для страницы `/o-nas/` указать `/en/about/`, `/de/uber-uns/`.  

### 1.10. Sitemap.xml

**Что это:** файл-карта сайта — список всех страниц для поисковика.  
**Зачем нужно:** поисковик быстрее узнаёт о новых страницах. Не заменяет индексацию, но ускоряет.  
**Кто использует:** Google, Яндекс, Bing.  
**Пример:** `https://site.ru/sitemap.xml` — внутри `<url>` для каждой страницы, с приоритетом и частотой обновления.

## ЧАСТЬ 2. 11 TV — ПОЛЯ В КАРТОЧКЕ ДОКУМЕНТА

Открываются на вкладке **SEO** в форме редактирования страницы. Управляют SEO конкретной страницы.

### 2.1. `seo_title` — SEO Title

**Что это:** переопределение заголовка `<title>` для этой страницы.  
**Зачем нужно:** стандартный title формируется как «Название страницы — Название сайта». Если хочешь свой — вписываешь здесь.  
**Пусто → авто:** `pagetitle — site_name`  
**Заполнено →** берётся твой текст.  
**Пример:** вместо «О компании — Vitamin C» пишешь «О компании Vitamin C — стратегические коммуникации в Берлине».  
**Когда заполнять:** важные страницы, лендинги, статьи — где хочешь усилить ключами.  

### 2.2. `seo_description` — SEO Description

**Что это:** переопределение `<meta name="description">` для этой страницы.  
**Зачем нужно:** свой текст в серой строке под заголовком в поиске.  
**Пусто → авто:** берётся из `description` документа, потом из `introtext` (первые 160 символов), потом из `content` (первые 160 символов).  
**Заполнено →** берётся твой текст.  
**Пример:** «Мы — агентство стратегических коммуникаций в Берлине. Позиционирование, Thought Leadership, PR для бизнеса.»  
**Когда заполнять:** важные страницы, где хочешь точный текст для поиска.  

### 2.3. `seo_keywords` — SEO Keywords

**Что это:** список ключевых слов для устаревшего тега `<meta name="keywords">`.  
**Зачем нужно:** ни для чего. Google игнорирует с 2009, Яндекс с 2022.  
**Пусто →** не выводится (по умолчанию).  
**Заполнено →** выводится только если включена настройка `Output keywords` в модуле.  
**Когда заполнять:** никогда. Оставь пустым.  

### 2.4. `seo_og_image` — OG Image

**Что это:** картинка для превью страницы в соцсетях.  
**Зачем нужно:** когда делишься ссылкой в Telegram, VK, Facebook — показывается картинка. Это она.  
**Рекомендуемый размер:** 1200×630 пикселей.  
**Пусто → авто:** берётся логотип (`seo_org_logo`), потом общая OG-картинка (`og_default_image`), потом первое изображение из контента.  
**Заполнено →** берётся твоя картинка.  
**Кнопка Browse:** рядом с полем — открывает медиабраузер.  
**Пример:** для статьи «SEO в 2026» — картинка с обложкой статьи.  
**Когда заполнять:** статьи, товары, лендинги — где картинка уникальна.  

### 2.5. `seo_canonical` — Canonical URL

**Что это:** «главный» URL страницы, если она доступна по нескольким адресам.  
**Зачем нужно:** чтобы поисковик не считал дубликаты разными страницами и не размывал трафик.  
**Пусто → авто:** текущий URL страницы.  
**Заполнено →** берётся указанный URL.  
**Формат:** полный URL с `https://`, без слэша в конце.  
**Пример:** `https://site.ru/o-nas`.  
**Когда заполнять:** если страница — дубликат другой, или хочешь указать на неё канонический URL.  

### 2.6. `seo_noindex` — Robots (indexing)

**Что это:** управление индексацией — пускать страницу в поиск или нет.  
**Зачем нужно:** технические страницы («спасибо за заказ», 404, устаревшие акции) не должны попадать в поиск.  
**Варианты:**
- **Index + Follow** — индексировать, обходить ссылки (по умолчанию).
- **Noindex + Follow** — не индексировать, но обходить ссылки.
- **Noindex + Nofollow** — полный запрет.
- **Noindex + Noarchive** — не индексировать, без кэша.  
**Что в HTML:**
- Index + Follow → тег **не выводится** (это дефолт).
- Остальные → `<meta name="robots" content="noindex, nofollow">`.  
**Когда что выбирать:**
- «Спасибо за заказ» → Noindex + Nofollow.
- «Политика конфиденциальности» → Index + Follow (её ищут).
- Устаревшая акция → Noindex + Nofollow.

### 2.7. `seo_schema_type` — Schema.org type

**Что это:** тип страницы для структурированных данных.  
**Зачем нужно:** поисковик понимает, что на странице, и показывает расширенный сниппет — со звёздочками, датой, ценой, FAQ.  
**Варианты:**
- **WebPage** — обычная страница (по умолчанию).
- **Article** — статья, лонгрид, блог.
- **NewsArticle** — новость.
- **BlogPosting** — запись в блоге.
- **Product** — карточка товара.
- **Service** — описание услуги.
- **FAQPage** — страница с вопросами-ответами.  
**Что даёт:**
- Product + отзывы → ★★★★★ в выдаче Google.
- Article → дата и автор в Яндекс.Новостях.
- FAQPage → раскрывающиеся ответы прямо в поиске.  
**Когда что выбирать:**
- «Купить iPhone» → Product.
- «Как выбрать хостинг» → Article.
- «Контакты» → WebPage.

### 2.8. `seo_hreflang` — Hreflang

**Что это:** управление языковыми версиями страницы.  
**Зачем нужно:** если сайт мультиязычный — говорим поисковику: «вот русская версия, вот английская».  
**Пусто → авто:** берётся из данных EvoBabel (если плагин активен).  
**Заполнено `exclude` →** страница исключается из hreflang-связки.  
**Глобальный выключатель:** в модуле `Enable hreflang` → No/Yes.  
**Пример:** страница без переводов — ставим `exclude`, чтобы Google не искал несуществующие версии.  
**Когда включать:** только когда реально есть переводы страниц и настроен EvoBabel.  

### 2.9. `sitemap_priority` — Sitemap priority

**Что это:** относительный приоритет страницы в `sitemap.xml`.  
**Зачем нужно:** подсказка поисковику, насколько страница важна. **Google игнорирует с 2017**, Яндекс — учитывает частично.  
**Значения:**
- `1.0` — главная.
- `0.8` — важные разделы.
- `0.5` — обычные (по умолчанию).
- `0.3` — второстепенные.
- `0.1` — архивы.  
**Когда менять:** почти никогда. Оставь 0.5, для главной — 1.0.  

### 2.10. `sitemap_changefreq` — Sitemap change frequency

**Что это:** как часто страница обновляется.  
**Зачем нужно:** подсказка поисковику, как часто проверять страницу. **Google игнорирует с 2017**.  
**Значения:** `always`, `hourly`, `daily`, `weekly`, `monthly`, `yearly`, `never`.  
**Когда менять:**
- Новости → daily.
- Каталог → daily.
- Обычные → monthly (по умолчанию).
- Архивы → never.

### 2.11. `sitemap_exclude` — Sitemap exclude

**Что это:** исключить страницу из `sitemap.xml`.  
**Зачем нужно:** технические страницы не должны быть в карте сайта.  
**Поставить галочку →** страница не попадёт в `sitemap.xml`.  
**Разница с `seo_noindex`:**
- `sitemap_exclude` — убирает из карты сайта.
- `seo_noindex` — запрещает индексацию.  
**Пример:** страница «Спасибо за заказ» — ставим оба: не в карте и не в поиске.

## ЧАСТЬ 3. 11 НАСТРОЕК МОДУЛЯ — ГЛОБАЛЬНЫЕ

Открываются в **Модули → seoVolo Settings**. Работают на всём сайте, не на одной странице.

### 3.1. `seo_org_name` — Organization name

**Что это:** юридическое название организации.  
**Зачем нужно:** попадает в Schema.org Organization. Google использует для панели знаний.  
**Пример:** `ООО «Витамин C»`.  
**Когда заполнять:** всегда — это базовые данные сайта.  

### 3.2. `seo_org_logo` — Organization logo

**Что это:** URL логотипа организации.  
**Зачем нужно:** попадает в Schema.org Organization + используется как fallback для OG-картинки.  
**Рядом кнопка Browse** — открывает медиабраузер.  
**Пример:** `/images/logo.png`.  
**Когда заполнять:** всегда.  

### 3.3. `seo_org_phone` — Organization phone

**Что это:** телефон организации.  
**Зачем нужно:** попадает в Schema.org Organization.  
**Пример:** `+7 (495) 123-45-67`.  
**Когда заполнять:** если есть публичный телефон.  

### 3.4. `seo_org_email` — Organization e-mail

**Что это:** email организации.  
**Зачем нужно:** попадает в Schema.org Organization.  
**Пример:** `info@site.ru`.  
**Когда заполнять:** если есть публичный email.  

### 3.5. `seo_org_address` — Organization address

**Что это:** адрес организации.  
**Зачем нужно:** попадает в Schema.org Organization.  
**Пример:** `Москва, ул. Ленина, 1`.  
**Когда заполнять:** если есть физический адрес.  

### 3.6. `og_default_image` — Default OG image

**Что это:** общая OG-картинка по умолчанию.  
**Зачем нужно:** используется для страниц без своей OG-картинки.  
**Рядом кнопка Browse** — открывает медиабраузер.  
**Рекомендуемый размер:** 1200×630.  
**Логика:** если у страницы нет своей картинки — берётся эта.  
**Пример:** `/images/og-default.jpg`.  

### 3.7. `seo_title_separator` — Title separator

**Что это:** разделитель между заголовком страницы и названием сайта в `<title>`.  
**Зачем нужно:** настраиваешь, как выглядит автоматический title.  
**По умолчанию:** ` — ` (длинное тире с пробелами).  
**Пример:** «О компании — Vitamin C» (с тире). Или «О компании | Vitamin C» (с вертикальной чертой).  
**Когда менять:** если хочешь свой стиль разделителя.  

### 3.8. `seo_twitter_site` — Twitter/X site

**Что это:** @username сайта в Twitter/X.  
**Зачем нужно:** попадает в Twitter Cards. Twitter/X показывает, от кого твит.  
**Пример:** `@vitaminc`.  
**Когда заполнять:** если у сайта есть аккаунт в Twitter/X.  

### 3.9. `seo_twitter_creator` — Twitter/X creator

**Что это:** @username автора контента в Twitter/X.  
**Зачем нужно:** попадает в Twitter Cards. Показывает авторство.  
**Пример:** `@ivan_petrov`.  
**Когда заполнять:** если у автора контента есть аккаунт.  

### 3.10. `seo_keywords_enabled` — Output keywords

**Что это:** выводить ли `<meta name="keywords">`.  
**Зачем нужно:** ни для чего — тег устарел.  
**По умолчанию:** No.  
**Когда включать:** никогда. Оставь No.  

### 3.11. `seo_hreflang_enabled` — Enable hreflang

**Что это:** глобальный выключатель hreflang.  
**Зачем нужно:** включить/выключить вывод языковых версий для всего сайта.  
**По умолчанию:** No.  
**Когда включать:** только когда реально есть мультиязычность и настроен EvoBabel. Иначе Google ругается на несуществующие URL.

## ЧАСТЬ 4. ШПАРГАЛКА

### 4.1. Минимум для запуска

Заполни в модуле `seoVolo Settings`:
- **Organization name**
- **Organization logo**
- **Default OG image**

Всё. Остальные TV оставь пустыми. Работает автоматически.

### 4.2. Что заполнять на страницах

| Тип страницы | Что заполнять |
|---|---|
| Обычная | ничего |
| Важная | `seo_title`, `seo_description`, `seo_og_image` |
| Статья | + `seo_schema_type` = Article |
| Товар | + `seo_schema_type` = Product |
| Техническая | `seo_noindex` = Noindex + Nofollow, `sitemap_exclude` |
| Дубликат | `seo_canonical` |

### 4.3. Что не трогать

- `seo_keywords` — оставить пустым.
- `seo_hreflang` — пока нет мультиязычности.
- `seo_keywords_enabled` — оставить No.
- `seo_hreflang_enabled` — оставить No.
- `sitemap_priority`, `sitemap_changefreq` — оставить по умолчанию.

### 4.4. Кто что использует

| Тег | Кто использует |
|---|---|
| Title | Google, Яндекс, Bing |
| Description | Google, Яндекс, Bing |
| Keywords | никто |
| Canonical | Google, Яндекс, Bing |
| Robots | Google, Яндекс, Bing |
| Open Graph | Telegram, VK, Facebook, WhatsApp |
| Twitter Cards | Twitter/X |
| Schema.org | Google, Яндекс |
| Hreflang | Google, Яндекс |
| Sitemap | Google, Яндекс, Bing |
