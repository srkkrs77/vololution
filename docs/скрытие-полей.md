Ниже — стандартный набор полей формы документа в MODX Evo 1.0.x. Названия беру из самой формы, не из головы, но в твоей сборке пара полей может называться иначе — проверка займёт секунду:

на странице редактирования документа открой консоль браузера (F12) и выполни


[...document.querySelectorAll('#documentFrm [name]')].map(e => e.name).filter((v,i,a) => a.indexOf(v) === i).join(', ')
Получишь точный список имён именно твоей админки. Если что-то из таблицы не совпадёт — скажи, поправлю.

Плюс легаси-поля из 0.9.6, если у тебя включены приватные документы: privateweb — доступ к странице только после входа, privatemgr — то же для админки.

Несколько полей сразу


Одним вызовом, а не двадцатью строками:

mm_hideFields('longtitle,introtext,description,hidemenu,isfolder,donthit,target');


Только на конкретном шаблоне (ID смотри в «Элементы → Шаблоны», это третий аргумент):

mm_hideFields('longtitle,introtext', '', '5');


Что прятать не стоит
pagetitle — обязательное поле, без него не сохранится (или сохранится с пустым заголовком).
template — без него не сменить шаблон на странице.
parent — без него не перенести страницу.
published — без него контент-менеджер не сможет снять/поставить страницу.
Если задача — «упростить форму для контент-менеджера», обычно оставляют pagetitle, content (или TV с блоками), template, parent, published, а прячут alias, description, introtext, longtitle, menuindex, cacheable, searchable, donthit, richtext, contentType, target.

Проверка после сохранения
Правила применяются через JS при загрузке формы, поэтому: очистить кэш → обновить страницу редактирования (Ctrl+F5). Если поле осталось — имя не совпало, сверь по консольному списку выше.
