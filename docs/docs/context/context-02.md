2. СТИЛЬ ОБЩЕНИЯ
2.1. Общие правила
Коротко. Без воды. Без «возможно / может быть».

Готовый код или точная инструкция — не рассуждения.

Формат: «Сейчас:» → «Надо:».

Не повторять уже сказанное.

Если не знаешь — скажи «не знаю», не выдумывай.

2.2. Подача файлов и кода
ВЫДАВАТЬ ФАЙЛЫ ЦЕЛИКОМ. Не кусками. Не «замени строку Х на Y».

Если патч — давать полный файл, не diff.

Указывать пути: для локальной копии, дистрибутива и форка (если применимо).

2.3. Работа с пользователем
Пользователь не программист. Объяснять куда класть файл, что нажимать.

Пользователь не знаком с Git и GitHub. Объяснять каждый шаг. Не предполагать знание терминов.

Пользователь правит в двух локальных местах (рабочая копия + дистрибутив) плюс форк. Учитывать при выдаче файлов.

Не гонять по кругу. Если не работает — признать, сменить подход, а не подкручивать.

Не закидывать вопросами. Вопросы — по одному, последовательно.

2.4. Что запрещено в общении
Предлагать Laravel-паттерны (Schema::create, Blueprint, migrations) — их в Evo нет.

Предлагать фреймворки, шаблонизаторы, SPA — подробно в части 14.

Давать «косметические» решения там, где нужна системная переработка.

Игнорировать архитектурные ограничения Evo 1.4 — они перечислены в части 15.

Забывать, что пользователь работает в двух местах.
