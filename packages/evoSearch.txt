Сниппет для поиска по сайту с учётом морфологии (русский и английский языки) и релевантности. Работает в связке с DocLister, который у вас уже установлен.

Оговорка: В официальном каталоге Evolution CMS он помечен как Legacy, но в репозитории есть релиз «Ready for php 8.1» от августа 2022 года. Прямых тестов на PHP 8.5.10 нет, поэтому после установки обязательно проверьте php_errors.log. Если появятся ошибки с указанием файла и строки — присылайте, дам точные правки.

Важное условие работы: Для поиска требуется полнотекстовый индекс MySQL (FULLTEXT). Без него поиск работать не будет — это не ошибка PHP, а требование к базе данных. Индексация запускается из админки, поля content_with_tv и индексы создаются автоматически при первом запуске.

Для настройки поиска нужны TV-параметры, которых у вас пока нет. Логика здесь простая: evoSearch по умолчанию индексирует только стандартные поля документа (pagetitle, longtitle, description, introtext, content), а всё, что вы хотите искать дополнительно, нужно вынести в отдельные TV-параметры и перечислить их в настройках плагина.

Для проверки достаточно одного TV, но в реальном проекте их может быть несколько.

Вариант 1. Универсальный тестовый TV

Создайте TV-параметр:

Имя: search_content

Подпись: Дополнительный контент для поиска

Тип ввода: Textarea (или RichText, если хотите форматирование)

Привязать к шаблонам: тот шаблон, который используется у тестовых статей

Затем откройте любую статью, вкладку TV, и заполните search_content каким-нибудь уникальным текстом, например: «Этот текст находится только в TV-параметре и должен находиться через поиск».

Вариант 2. Реалистичный набор TV

Если хотите сразу увидеть, как это работает в боевых условиях, создайте два TV:

search_content — для основного дополнительного текста.

search_keywords — для ключевых слов.

Заполните их у тестовых статей разными словами.

Как прописать TV в настройках плагина
Перейдите в Элементы → Плагины.

Откройте evoSearch на редактирование.

Перейдите на вкладку «Конфигурация».

Найдите поле «Имена TV для поиска» (в разных версиях может называться TvNames или TV names to search).

Впишите туда имена ваших TV через запятую, без пробелов:
search_content,search_keywords

Сохраните плагин.

Запуск индексации
После добавления TV в настройки плагина:

В той же конфигурации плагина установите:

«Переиндексировать все» = 1

«Строк за сеанс индексировать» = 10000

«Первая строка переиндексации» = 0

Сохраните плагин.

Откройте и пересохраните любой документ — это вызовет событие onDocFormSave, которое запустит индексацию.

Верните настройки обратно: «Переиндексировать все» = 0, «Строк за сеанс» = 1.

Теперь при поиске слова, которое есть только в search_content, evoSearch должен его найти.

Создайте страницу «Поиск» с вызовом сниппета:


[[evoSearch?
&tpl=`@CODE:<div><a href="[+url+]">[+pagetitle+]</a><p>[+extract+]</p></div>`
]]

Введите в поиске «уникальное_слово_раз» — должно найтись.

Важное замечание
Если вы изменили список TV в настройках плагина, индексацию нужно запускать заново — иначе старые данные останутся в индексе без учёта новых TV.

Начните с создания одного TV search_content — этого хватит, чтобы проверить, работает ли механизм в принципе.

Пример формы для страницы «Поиск»:

<form action="[~[*id*]~]" method="get">
    <input name="search" type="text" placeholder="Поиск..." value="[+search.value+]">
    <button type="submit">Найти</button>
</form>

[[evoSearch?
&tpl=`@CODE:<div><a href="[+url+]">[+pagetitle+]</a><p>[+extract+]</p></div>`
]]
